# InfoHub 当前状态与缺口

**审查日期**：2026-07-30  
**用途**：开发前真实基线，不把设计或空文件当作已完成功能。

## 1. 当前技术结构

- vinext / Next.js / React
- Cloudflare Sites/Worker
- D1 + Drizzle
- GitHub Actions 运行采集器
- Moonshot Kimi K3 内容加工
- Supadata、Get笔记和 baoyu 文字稿能力

## 2. 已经存在

### 页面

- 每日首页和五类板块基础展示
- 最近日期入口
- 内容详情基础页面
- 感兴趣列表
- 完成阅读和下一篇
- 详情回到顶部、返回恢复位置的基础实现
- 本地高亮基础实现
- 板块顺序和显示偏好
- `/admin` 信息源和部分设置

### 数据与接口

- `sources`、`app_settings`、`contents`
- `user_preferences`、`user_content_states`
- `notes`、`highlights`、`reading_progress`
- `/api/feed`、`/api/ingest`、`/api/library`
- 板块偏好接口

### 采集与服务

- Follow Builders、技术动态 X、论文和 GitHub Trending 采集路径
- YouTube RSS 发现
- Supadata 文字稿路径
- Kimi按来源加工
- 单个来源失败时继续其他来源
- Moonshot、Supadata、Get笔记凭据已分别做过轻量验证
- Get笔记已真实返回过完整 YouTube 文字稿

## 3. 仍需完成

### 每日固定工作流

- 将现有采集过程显示为采集、AI整理、质量检查、发布四个状态
- 每天运行一次而不是每小时
- 去重后再调用收费服务
- 自动重试最多 5 次
- 保存失败原因并提供重试

### 管理后台

- 工作流状态、来源统计、历史和重试
- YouTube候选池和管理员提交链接
- 内容筛选、预览、重新加工、发布和撤下
- 服务配置状态和当前 AI 加工规则

### 内容可读性

- 板块总结
- 论文的普通人解释、价值和局限
- GitHub的产品化介绍、门槛和热度语境
- X的中文内容和清楚直达链接
- YouTube/播客的 Takeaways 与详细中文文章
- 简单明确的质量检查

### 私人阅读

- 完整的未读、阅读中、已读状态
- 阅读进度服务端同步
- 高亮、批注和笔记跨端同步
- 笔记归档和 Markdown 导出
- 普通用户与管理员权限隔离验收

### 推送

- 用户主动订阅和取消
- 每日内容概览通知
- 不支持或拒绝通知时平稳降级

## 4. 当前遗留改动

工作区中存在尚未验收的数据库迁移和多个空的工作流/服务文件。这些内容来自此前过重的工作流设计，不能直接视为已完成。正式开发前应审查并收缩为轻量数据结构，保留现有数据，删除不需要的空占位和复杂设计。

## 5. 实施注意事项

- 不重新采集数据作为 UI 开发前提，优先使用现有真实结果和 mock。
- 外部 API测试保持单条、轻量，避免浪费额度。
- `.env.local` 中的密钥不得输出或提交。
- 保留用户现有改动和真实内容。
- 未经用户授权，不部署、不修改线上 Secrets、不推送远程仓库。
