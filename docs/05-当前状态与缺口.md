# InfoHub 当前状态与后续计划

**更新日期：2026-08-05**

## 当前已实现

- 用户端四个区域：日报、精选、收藏、我的。
- 日报只展示 X、热门论文、GitHub Trending。
- 独立精选编辑后台及草稿、预览、发布、撤回状态。
- 收藏内容快照、阅读位置、划线与关联笔记。
- 本地私人数据导出与恢复。
- 三种主题和每日一次 Web Push。
- GitHub Actions 每日采集、5 次来源重试和 GitHub Pages 发布。
- 日报月度静态归档。

## 上线前操作

- 部署新版 Cloudflare Worker，使精选 API 生效。
- 构建并发布新版 GitHub Pages，使 `admin.html` 和 `generated-curated.json` 上线。
- 检查 Worker 的 GitHub Token 具有目标仓库 **Contents: Read and write** 权限（当前旧 Token 若只有 Actions 权限，需要更新）。
- 用一篇测试内容完成“草稿 → 预览 → 发布 → 用户端出现 → 撤回”验收。

## 暂不实现

- 用户账号、邮箱登录和跨设备自动同步。
- 普通用户提交链接。
- 自动处理精选链接、YouTube 或播客文字稿。
- 通用工作流后台与复杂业务数据库。

## 一季度后复盘

若产品连续稳定使用超过一个季度，评估：公开内容规模、Cloudflare KV 草稿量、活跃设备、备份频率和恢复需求。只有数据量或可靠性要求达到必要程度时，再引入数据库或对象存储，并补充自动异地备份、保留周期和恢复演练。
