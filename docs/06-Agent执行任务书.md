# InfoHub 开发执行任务书（轻量版）

## 1. 总目标

在现有产品上补齐：

1. 每日固定四步内容生产
2. 简单可用的管理后台
3. 更容易判断和阅读的公共内容
4. 私人的感兴趣、阅读和笔记闭环

不建设通用工作流、复杂版本系统、分布式队列或无关基础设施。

## 2. 开发顺序

### A. 先检查并收缩现有数据库改动

- 保留现有数据和已发布内容。
- 优先复用现有表。
- 只增加每日任务、来源结果和内容处理状态所需的最少字段或表。
- 删除或不采用尚未使用的复杂工作流、Artifact和Prompt版本设计。
- 数据迁移必须向后兼容。

### B. 固定四步后端

实现：采集 → AI 整理 → 质量检查 → 发布。

- 每步保存状态和简明错误。
- 单个来源失败不阻塞其他来源。
- 最多自动重试 5 次。
- 支持重试失败来源或内容。
- 去重后再调用收费服务。
- 已有文字稿可复用。

### C. 管理后台

- 工作流：今日四步状态、来源统计、失败原因、立即运行和重试。
- 候选内容：YouTube发现、管理员提交、批量处理。
- 内容管理：筛选、预览、编辑、重新加工、发布和撤下。
- 设置：信息源、频道、运行时间、服务配置状态和当前 AI 加工规则。

### D. 公共内容

- 首页使用五个板块。
- 每个板块先显示总结，再显示全部有效内容。
- 论文和 GitHub 使用普通人可读的科技媒体表达。
- X 保留直达链接。
- YouTube/播客使用 Takeaways + 详细中文文章。

### E. 私人阅读

- 感兴趣只在详情页操作。
- 完成未读、阅读中、已读。
- 保存阅读进度和返回位置。
- 实现准确选区高亮、批注、自由笔记和跨端同步。
- 普通用户不能看到管理员功能。

## 3. 文件协作规则

- 开工前检查 `git status`，不得覆盖已有用户修改。
- 多个 Agent 同时工作时必须划分文件范围，不能同时编辑同一文件。
- 不修改任务范围外的文案和样式。
- 不删除现有真实采集结果。
- 不输出或提交任何真实密钥。

## 4. 验证

每个功能完成后运行相关测试；最后运行项目实际存在的 lint、test 和 build 命令。

必须验证：

- 来源失败不影响其他来源
- 去重和最多 5 次重试
- 质量通过自动发布
- 后台可查看错误并重试
- 普通用户无管理权限
- 私人阅读数据按用户隔离
- 手机端核心操作可用
