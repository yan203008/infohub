# InfoHub 数据、权限与 API 规范（轻量版）

**版本**：v1.1

## 1. 三类数据

### 公共数据

- 已发布内容、板块总结、关键词和原始链接
- 公开日期、来源和内容类型

### 管理员数据

- 候选内容
- 每日任务和四步状态
- 失败原因、重试次数和服务状态
- 未发布的原始资料与文字稿
- 管理员提交的链接

### 用户私人数据

- 感兴趣与阅读状态
- 阅读进度
- 划线、批注和自由笔记
- 个人板块顺序和显示设置

管理后台不能查看其他用户的私人笔记正文。

## 2. 最小数据改动

优先复用现有 `sources`、`contents`、`user_content_states`、`notes`、`highlights` 和 `reading_progress`。

为管理后台新增或补足的最小记录：

### 每日任务

- 日期
- 状态
- 当前步骤
- 触发方式
- 开始/结束时间
- 成功、失败和发布数量

### 来源结果

- 所属每日任务
- 来源
- 状态
- 发现、新增和重复数量
- 最后错误

### 内容处理状态

- 所属每日任务和内容
- 当前步骤
- 状态
- 重试次数
- 最后错误
- 实际使用的文字稿服务或模型

不要求新增通用 Artifact、Prompt 版本、步骤依赖图或复杂服务计费表。完整文字稿可以沿用现有文档存储方式，只要能在重新加工时复用。

## 3. 内容状态

公共内容至少能表达：

```text
candidate → processing → published | failed
```

- candidate：仅管理员可见，尚未消耗文字稿服务
- processing：正在采集或加工
- published：质量通过并公开
- failed：处理失败，仅管理员可见

如现有代码需要临时使用 ready，可保留兼容映射，但公共 Feed 只能返回已通过并允许公开的内容。

## 4. 阅读状态

用户内容状态：

```text
unread → reading → completed
```

同时保存是否感兴趣，避免取消感兴趣时误删已有笔记。

## 5. API 能力

路由名称可以适配现有框架，第一版只要求以下能力。

### 公共

- 按日期获取公开内容和板块总结
- 获取公开内容详情
- 获取可用日期

### 登录用户

- 保存感兴趣和阅读状态
- 保存/获取阅读进度
- 新增、编辑和删除划线与笔记
- 保存个人板块偏好
- 导出笔记

所有私人请求必须由服务端当前登录身份确定用户，不能相信客户端传入的任意用户 ID。

### 管理员

- 查询今日任务和历史任务
- 立即运行每日任务
- 查询失败原因并重试失败来源或内容
- 查询和处理候选内容
- 提交链接
- 管理信息源和频道
- 查询服务配置状态
- 编辑当前 AI 加工规则

### 内部采集

- 现有采集器入库接口继续使用服务器密钥保护
- 重复请求必须去重，避免重复发布和重复消耗 API

## 6. 密钥

服务器环境变量包括：

- `MOONSHOT_API_KEY`
- `MOONSHOT_BASE_URL`
- `MOONSHOT_MODEL`
- `SUPADATA_API_KEY`
- `GETNOTE_API_KEY`
- `GETNOTE_CLIENT_ID`
- `INGEST_SECRET`

密钥不能进入前端、公共接口、数据库明文、日志或 GitHub。后台只显示是否配置。

## 7. 权限

- `/admin/**` 和管理员 API 必须验证管理员身份。
- 普通用户即使知道地址也不能访问管理数据。
- 普通用户不能提交链接、添加频道或触发内容加工。
- 用户私人查询必须限制为当前用户。
- 错误日志必须隐藏 Key、Cookie 和私人笔记正文。

## 8. 重试与去重

- 内容优先使用平台 ID 去重，否则使用规范化 URL。
- 每日任务再次运行只补充新增内容。
- 每条失败内容最多自动重试 5 次。
- 重试 AI 加工时复用原始资料和文字稿。
- 发布使用 upsert，不能生成重复卡片。
