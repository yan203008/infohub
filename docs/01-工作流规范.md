# InfoHub 固定工作流规范

**版本**：v1.1  
**原则**：只实现固定内容生产流程，不建设通用任务调度平台。

## 1. 两类运行

### 每日自动运行

每天一次处理 Follow Builders、技术动态 X、热门论文和 GitHub Trending。

### 管理员精选运行

管理员选择 YouTube 候选，或主动提交 YouTube、播客和文章链接后立即处理。未选择前不调用文字稿服务。

## 2. 四个固定步骤

| 步骤 | 输入 | 输出 | 失败后的操作 |
|---|---|---|---|
| 采集 | 已启用来源或管理员链接 | 去重后的原始内容 | 自动重试；后台可重新采集 |
| AI 整理 | 原始文本、摘要、README或文字稿 | 类型化中文内容 | 自动重试；后台可重新加工 |
| 质量检查 | 加工结果 | 通过或明确失败原因 | 后台修正后重试 |
| 发布 | 通过检查的内容 | 当日公开内容 | 后台重新发布 |

状态统一为：`pending`、`running`、`completed`、`failed`。

## 3. 基本规则

- 每天只运行一次正式每日任务；手动再次运行只补充新增内容。
- 使用平台内容 ID 或规范化 URL 去重。
- 单个来源或单条内容失败不阻塞其他内容。
- 每个失败动作最多自动尝试 5 次。
- 最终失败保存简明错误原因，并在管理后台显示重试按钮。
- 重试时复用已成功获取的原始资料和文字稿，避免重复付费。
- 测试运行不得进入公开首页。
- 发布使用 upsert，不能产生重复卡片。

## 4. 文字稿处理

1. 系统发现 YouTube 新视频时只进入候选区。
2. 管理员点击处理后才调用 Get笔记或 Supadata。
3. 两个服务轮换使用；一个失败时尝试另一个。
4. 保存成功文字稿，后续 AI 重加工直接复用。
5. 两个服务均失败并达到重试上限后，显示人工重试。

## 5. 后台需要记录的最少信息

### 每日任务

- 日期
- 开始和结束时间
- 当前步骤
- 总状态
- 发现、成功、失败和发布数量

### 每个来源

- 来源名称
- 状态
- 发现、新增和重复数量
- 最后错误

### 每条内容

- 标题和原始链接
- 当前步骤和状态
- 重试次数
- 使用的文字稿服务或 AI 模型
- 最后错误

不要求实现任意步骤编排、复杂依赖图、分布式锁、通用任务队列或多层产物版本系统。

## 6. 后台呈现示例

```text
采集：已完成，获取 38 条
AI 整理：处理中，已完成 24/38
质量检查：等待处理
发布：等待处理
```

失败示例：

```text
热门论文｜AI 整理失败
原因：返回内容缺少“普通人价值”
已尝试：5 次
[重新加工]
```
