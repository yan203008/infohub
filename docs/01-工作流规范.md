# InfoHub 工作流规范

## 日报自动流程

每天一次：采集 X、热门论文、GitHub Trending → Kimi 整理 → 质量检查 → 发布 → 月度归档 → 通知。

- X 包含 Follow Builders 与技术动态 X。
- 单个来源失败不阻塞其他来源。
- 每个失败来源最多自动重试 5 次。
- 发布使用稳定内容 ID 去重。
- 运行情况以 GitHub Actions 日志和 `app/generated-run-summary.json` 为准。
- 不建设通用工作流编排后台。

## 精选编辑流程

管理员在独立后台输入已经整理好的文章：

```text
新建 → 保存草稿 → 预览 → 发布 → 已发布/待展示
                            ↘ 失败后保留原因并可重新发布
```

精选不会调用 Kimi、Get笔记、Supadata 或文字稿服务。未来日期内容可以提前发布到公共文件，但用户端到达展示日期后才显示。撤回会从公共文件删除，同时保留后台草稿记录。

## 状态

精选状态固定为：`draft`、`publishing`、`scheduled`、`live`、`failed`、`withdrawn`。
