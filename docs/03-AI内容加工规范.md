# InfoHub AI 内容加工规范

**版本**：v1.1  
**目标读者**：关注 AI 行业但不是算法/研发人员的用户。

## 1. 总则

AI 的职责是解释和增加可读性，不是筛选、推荐或扩写事实。

所有加工必须：

- 忠于给定原始资料
- 区分“原文事实”和“编辑解释”
- 不猜测无法访问的短链接、图片、引用或缺失上下文
- 不把论文摘要外的结果写成事实
- 不把 GitHub README 未声明的功能写成事实
- 不删减 YouTube/播客的重要论点、案例、条件和例外
- 面向非技术读者解释，但保留必要准确性
- 生成结构化输出，供质量检查和页面渲染

## 2. 每条内容的基本输出

每条内容至少包含以下信息；具体存储结构可以沿用现有内容模型，不要求为此建设通用产物系统：

```json
{
  "title_zh": "中文标题",
  "decision_card": {
    "what_it_is": "这是什么",
    "what_it_reflects": "反映了什么",
    "why_it_matters": "为什么值得了解",
    "audience": ["适合的角色"],
    "technical_level": "low | medium | high | professional",
    "technical_percentage": 35,
    "estimated_read_minutes": 4,
    "completeness": "complete | partial | insufficient"
  },
  "keywords": ["3至6个中文关键词"],
  "detail": {},
  "editorial_notes": [],
  "source_url": "原始链接"
}
```

`technical_percentage` 是 AI 阅读辅助估算，不是科学统计。页面必须同时展示等级并说明估算性质。

等级：

- 0–20：low
- 21–50：medium
- 51–75：high
- 76–100：professional

## 3. 板块级总结

当某板块全部有效条目完成单条加工后，根据单条结构化结果生成：

```json
{
  "section": "papers",
  "contains": ["本日包含的主题"],
  "trends": ["共同反映的趋势"],
  "composition": ["内容构成"],
  "technical_level": "high",
  "technical_percentage": 60,
  "completeness_note": "可选的完整度说明"
}
```

规则：

- 不做“最值得读”排名
- 不删除或隐藏单条内容
- 趋势必须能够从至少一条输入得到支持；跨条归纳要使用“这些内容共同显示/可能反映”等审慎语言
- Follow Builders 应统计完整、部分、信息不足的数量
- GitHub 应说明 AI 与非 AI 项目构成

## 4. Follow Builders / 技术动态 X

### 决策卡

- 谁在说什么/文章解决什么问题
- 反映的产品、职业、组织或行业变化
- 为什么目标用户值得了解
- 内容完整度
- 专业门槛

### 详情结构

```text
完整中文翻译或详细中文介绍

原文信息
编辑解释（明确标记）
内容完整度与缺失说明

链接直达：https://完整网址
```

规则：

- 原文只有短链接：写明信息不足，不猜测链接内容
- 原文被截断：翻译已有部分并指出截断位置
- 政治、生活或非 AI 内容仍可展示，不因相关性删除
- 不能把作者公开背景写成推文本身内容；如补充必须标记为背景

## 5. 热门论文

### 决策卡

- 这篇论文研究什么
- 它反映的研究趋势
- 普通用户为什么可能需要知道
- 阅读门槛与专业占比

### 详情固定结构

1. **研究什么问题**
2. **研究者发现了什么**
3. **用普通语言解释**
4. **对普通人的生活或工作有什么启发**
5. **这篇论文不能证明什么**
6. **必要术语**（最多 3 个）
7. **论文原始链接**

规则：

- 只根据标题、摘要和明确提供的论文元数据
- 使用“论文报告/在给定实验中/作者声称”，避免把结果绝对化
- “普通人价值”可以说明趋势、产品成本、工作方式或风险判断，不得编造直接应用
- 标题应优先表达实际问题，不直接堆论文方法名

## 6. GitHub Trending

### 决策卡

- 用产品语言说明这是一个什么工具/产品
- 解决什么问题
- 对非开发用户的趋势价值
- 使用门槛与专业占比

### 详情固定结构

1. **这是什么**
2. **解决了什么问题**
3. **实际可以用来做什么**
4. **为什么最近受到关注**
5. **适合什么人**
6. **使用门槛**
7. **需要注意什么**
8. **热度与基本信息**
9. **项目直达链接**

热度必须包含：

- Stars 总量
- 今日新增 Stars（可获取时）
- 当日榜单位置或同榜单相对热度语境
- 最近更新时间

规则：

- 采用科技媒体产品介绍语气
- 技术栈只在帮助判断使用门槛时出现
- 非 AI 项目照常展示，并解释其用途，不强行包装成 AI
- 不把 Stars 等同于质量或安全
- README、官网、Releases 链接必须可点击

## 7. YouTube / 播客

### 输入

- 标题、作者/频道、原始链接
- 完整文字稿
- 时间戳和总时长（可获取时）

### 决策卡

- 内容主要讨论什么
- 最重要的现实价值或观点
- 适合谁
- 阅读时间、门槛和专业占比

### 详情固定结构

```markdown
## 标题

### Takeaways
- 可应用或值得记住的要点

### 章节标题（起止时间戳）
完整、阅读友好的中文文章段落

### 章节标题（起止时间戳）
...

原始链接
```

规则：

- Takeaways 必须在文章前
- 章节按原内容顺序
- 章节必须使用真实时间戳；没有时间戳时明确标记
- 保留论点、论据、案例、步骤、条件、例外和重要细节
- 只删除口头禅、无信息赘词与完全重复
- 不能把完整转述压缩成普通摘要
- 长文字稿可以分段加工，但最终必须检查段落连续性、顺序和缺失

## 8. 普通文章

- 首页卡片遵循通用决策卡
- 详情以忠实的中文介绍或原文整理为主
- 清楚区分原文摘要、编辑解释和原始链接
- 不复制受版权保护的全文；只展示系统有权保存/处理的内容和合规摘要

## 9. AI 加工规则

- 每种内容类型维护一份当前加工规则。
- 管理员可以在设置中查看和修改。
- 修改后只影响后续加工；已有内容只在管理员主动点击“重新加工”时更新。
- 重新加工必须复用已有原始资料和文字稿。
- 第一版不做复杂版本比较、发布审批和回滚平台。

## 10. 质量检查

机器检查：

- schema 和必填字段
- 百分比范围
- URL一致性
- 数组和段落非空
- 类型特定章节是否齐全
- YouTube/播客时间戳顺序和覆盖率

AI辅助检查：

- 是否出现原始资料外的具体事实
- 是否把推断写成事实
- 是否过度删减
- 是否仍然大量堆砌术语而没有解释
- “不能证明什么”是否合理且不虚构

质量检查只返回通过或失败以及简明理由，不能根据价值判断删除内容。
